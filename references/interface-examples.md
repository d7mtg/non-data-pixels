# Interface examples and limits

Use these illustrative examples to decide what to keep in context. They are not strings to copy into every product.

## Remove repetition

If an action button already says “Call,” remove adjacent text that merely repeats the action. Keep appointment conditions and address details when they help a visitor decide.

A section heading can be unnecessary when its contents clearly identify it. Keep headings that aid navigation, distinguish groups, or provide semantic structure.

## Make numbers useful

A count belongs when it supports the reader's task. A missing-item count may help reconciliation but distract from entering an item.

If a selection control repeats a nearby count, simplify it while preserving scope. For example, clarify whether “Select all” includes results beyond the visible page. Combine a count with its action only when both remain clear and accessible.

## Show information at the right time

Show a submission state after the action occurs: “Sending” while it is in progress and “Pending review” only after the server accepts it. Keep file restrictions visible before selection when they affect preparation, and show a useful error for unsupported files.

An initial empty state should explain its purpose and offer a way to begin. Show results and totals when available. Describe an unavailable feature accurately rather than leaving an unexplained blank panel.

## Keep useful ways to start

An upload button and drag-and-drop can coexist: a button offers a keyboard-accessible route and opens the file picker. State actual restrictions instead of promising that any file is accepted.

Explain an unfamiliar model in a short first-use guide or accessible help. Keep distinctions beside content when they affect interpretation, even if the full guide is available elsewhere.

## Use the product's language

Prefer established field names over conversational prompts. Preserve the product's singular and plural conventions. Check labels alongside their values: a selected date range can supply context, but any remaining wording must still convey the correct scope and units.

## Fix false states at the source

If a search excludes people who already have access, “No matches” may be misleading. Within scope, fix the behavior or show the accurate state. For copy-only work, identify the behavior issue and use wording only for states whose meaning is known.

Verify the underlying meaning before shortening a label. A concise synonym does not fix an incorrect state.

## Avoid universal bans

“Coming soon,” delivery estimates, format hints, and helper text can be useful in one context and redundant in another. Keep a real condition or consequence when it matters to a decision.

Remove internal test instructions from ordinary product UI, but do not present a simulated or unavailable operation as completed. Inspect what a control actually changes before choosing its label.
